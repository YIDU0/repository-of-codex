# 第一阶段 Android 开发包说明

本包用于检查页面骨架及平台能力，不是可正式记账的业务版本。请勿将工时或工资填写在平台验证文件中。

## Cloud 文件读取错误

若 Codex 提示“无法加载此 Cloud 文件”，错误发生在客户端读取云端文件时，尚未进行 APK 安装。当前环境已核对在线，原 APK 存在且校验通过；不能仅凭此提示判断安装包损坏。

本轮另在 `/workspace/downloads` 准备了目录权限 755、文件权限 644 的独立副本：`worktime-stage1.apk`、约 91 MiB 的 `worktime-stage1.zip` 和 `SHA256SUMS.txt`。压缩包中 APK 的 SHA-256 与原包相同，仅包含 APK 及说明，不包含签名私钥。文件路径可读及压缩校验通过，不代表已验证客户端能够下载；若客户端仍报相同错误，需要另行确认文件导出能力或使用经授权的独立分发渠道。

用户复验后，新位置及压缩包仍无法通过 Cloud 文件链接打开，因此不再将这些链接当作可用的交付渠道。

## GitHub Actions 下载方案

用户已授权将第一阶段工程与下载流程推送到 `codex/stage1-download` 分支，并要求做好注明。工作流将阶段说明同步写入运行摘要和下载包；来源提交、构建地址及 APK 校验值随包提供。只将已成功完成并上传的对应运行视为可下载产物。

工程推送并构建成功后：

已成功构建并上传的首个版本：[打开运行 #1 的下载区域](https://github.com/YIDU0/repository-of-codex/actions/runs/39732332051#artifacts)，来源提交 `b0d27cc`。这是第一阶段开发验证版，业务和设备验收限制见随包的版本说明。

1. 打开 GitHub 仓库的 **Actions → Flutter quality**，选择对应分支、提交的运行记录。
2. 等待检查和构建成功。在运行详情底部 **Artifacts** 下载 `worktime-journal-stage1-debug`；下载时通常需要登录有权访问该仓库的 GitHub 账号。
3. 解压下载的 ZIP，获得 `worktime-journal-stage1-debug.apk`、`SHA256SUMS.txt`、`BUILD_INFO.txt` 和 `版本说明.md`，阅读说明后再将 APK 传入安卓手机。构建产物保留 7 天，过期后需重新构建。

工作流只上传 APK、校验文件和上述说明，不上传调试密钥、ADB 状态或 SDK 缓存。GitHub 会重新构建 APK，文件哈希应以该次运行随包提供的校验文件为准。不同机器的调试签名可能不同，不能承诺覆盖安装既有调试包。

## Android 安装

1. 将 `artifacts/worktime-journal-stage1-debug.apk` 传到自己的安卓手机。不要使用带 `x64-profile` 的模拟器包。
2. 从文件管理器打开 APK；按手机提示，临时允许该文件管理器安装应用，然后安装“工时手账”。
3. 应能看到中文首页和首页/月历/统计/设置四个入口。首页右上角的实验图标进入“开发版平台验证”。
4. 点击“写入并读取 SQLite”，记下次数；关闭并重新打开应用，点击“只读取已保存数据”，应读到同一次数。
5. 验证本地文件往返，再使用系统保存对话框导出验证 JSON，使用系统选择器选回同一个文件；读回次数应一致。
6. 按钮触发通知授权后，可检查排程及取消结果。排程成功仅表示已交给系统；实际送达、后台、重启和每日提醒规则后续分别验收。

验证页只存独立计数器。系统授权被拒绝时应显示结果，不影响页面导航。卸载会清除本地应用数据；当前没有正式账本或备份恢复功能。

这是 debug 签名，不是上架签名。首次测试目标机尚未确认；工程声明最低 Android 7.0/API 24，但没有完成最低版本或厂商系统兼容验收。安装失败请保留系统显示的完整原因及手机型号、系统版本。

## iPhone

Android APK 无法安装到 iPhone。当前只生成了 iOS 工程，尚无已构建的 iOS 安装包。后续须在 Mac/Xcode 上编译，按实际 Apple ID 或开发者会员条件选择真机开发测试或 TestFlight 路径；不承诺免签名或永久安装。

平台测试结论和已知限制见 [phase-1.md](phase-1.md)。
