# 开发与维护规则

状态：用户已确认，作为后续实现和审查基线。当前执行阶段 1，应用功能尚未实现。

## 1. 需求与变更

1. 已确认需求写入文档，新增或改变业务行为先更新需求与验收案例，再改实现。
2. 业务规则只有一个权威实现；页面、导出、统计和恢复不各写一套工资算法。
3. 正常实现、可逆修复和既定阶段验证持续推进，不因每个小步骤反复询问。需求变化、不可逆操作和外部发布明确说明后处理。
4. 不引入用户未要求的账号、后台、支付或广告；不为未来假想功能过度搭建框架。

## 2. 架构边界

1. 界面负责展示与输入，应用用例组织流程，领域层负责工资和日期规则，数据层负责持久化及平台适配。
2. 领域层不引用 Flutter 界面、数据库实现或通知插件。系统时间通过接口注入，测试不依赖真实当天日期。
3. 数据库、通知、文件系统通过清晰接口访问，平台差异集中封装，不散布在页面。
4. 工时、金额、状态和类别使用有明确单位的类型或字段命名；不靠字符串与隐含单位传递业务数据。
5. 只在真实存在重复行为或扩展需求时抽象，避免空层、万能工具类和巨型控制器。

## 3. 金额、日期与历史

1. 金额使用人民币分整数，工时使用百分之一小时整数；禁止浮点参与工资结算。
2. 工时精度、金额范围、单项舍入和汇总规则有固定测试；检查溢出和导入边界。
3. 日历日期与时间戳分离；周末分类根据记录日期；切换时区不迁移历史日期。
4. 已保存时薪和加减项使用快照，模板、当前费率或软件更新不能静默改变历史收入。
5. 历史纠错必须预览和确认，在事务内执行；记录更正摘要与计算规则版本。

## 4. 数据安全与可恢复性

1. 所有重要多表操作使用事务；保存失败不能伪装成功。
2. 数据库改动必须增加迁移并测试旧版本数据；禁止删除数据库作为升级方案。
3. 完整恢复先验证、再备份、再替换；备份失败不覆盖。导出和恢复格式独立版本化。
4. 默认不主动上传工时、收入或备注；不在日志中输出完整账本、备份内容或用户私人备注。
5. 明文备份导出前提示敏感内容；应用内备份与外部备份的保护范围说明清楚。
6. 系统云备份、数据清理与卸载行为在平台实现时明确核对并写入隐私说明，不宣称本地自动备份能抵御设备丢失。

## 5. 代码与依赖

1. 使用选定稳定版 SDK，记录版本与安装方式，提交应用依赖锁文件。
2. 依赖必须有用途、维护状态和许可依据；升级后运行受影响测试，不随意使用未验证最新版本。
3. 采用 Dart 官方格式化和静态检查；警告不能靠大范围忽略掩盖。
4. 命名表达业务含义；注释说明业务原因、单位和平台限制，不逐行复述代码。
5. 不把凭据、签名私钥、个人配置或生成的安装包提交到源码；构建产物放在受忽略目录或约定交付位置。
6. 保留用户既有改动；不自行重置、强推或覆盖用户工作。沿用当前隔离 checkout，未获请求不创建额外 worktree。

## 6. UI 与可访问性

1. 色彩、字号、间距和圆角集中管理，页面使用统一组件。
2. 重要金额、单位与保存结果明确；装饰不遮挡数据，颜色不作为唯一状态提示。
3. 表单错误指向具体字段，保留已填数据；加载、空白、失败、成功都有明确状态。
4. 小屏、安全区域、键盘和放大字体纳入组件与真机验收。
5. 时薪更正、覆盖导入、删除、覆盖记录等操作的确认内容必须具体，不只显示“确定吗”。

## 7. 测试与验证

1. 对金额、时薪历史、数据库迁移、备份恢复与提醒调度等有实际风险的逻辑写可失败的测试；不以验证实现细节的重复测试堆数量。
2. UI 展示、输入流程和真实持久化分别测试，模拟仓储通过不能代替数据库验证。
3. 每阶段运行相关检查并修复，再进入后续阶段。出现新改动或故障才扩大或重复检查。
4. Android 与 iOS 构建分别记录；两端通知和跨平台恢复必须有对应设备证据。
5. 通过、失败、跳过和未运行分别报告；编译通过、模拟器运行、真机安装和真机行为不能互相替代。
6. 不删除断言、跳过失败用例或降低验证规则来制造通过结果。

## 8. 文档与交付

1. 每个阶段给出本阶段变化、验证结果、已知限制和下一步；持续同步影响用户判断的发现。
2. 数据模型、计算规则、备份格式和公共接口变更同步更新文档。
3. 提交或交付围绕明确功能拆分，避免把工具链、大量业务与界面变动混成不可审查的一块。
4. 不未经授权推送、上架或发布环境；本地开发和构建持续推进，外部分发依用户选择执行。
5. 最终交付包含实际构建与测试记录、安装说明、恢复说明和后续维护入口；未完成项明确列出。
