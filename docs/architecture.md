# 当前工程架构与平台决策

本文件描述阶段 1 已实现的工程，不表示正式工时、工资或备份功能已完成。

## 代码边界

- `lib/app`：入口、Riverpod 依赖作用域、go_router 页面及四个导航入口。
- `lib/core/design_system`：奶油手账配色与统一主题。
- `lib/features/platform_probe`：仅开发版可进入的平台验证夹具。独立 SQLite 计数器、版本化 JSON、系统文件保存/打开、通知测试；不是工资模型或正式备份格式。
- `test`：文件边界、真实 SQLite 持久化/事务及页面导航检查。
- `integration_test`：设备上的 SQLite、原生文件对话框、通知排程和页面启动验证，结果须以实际运行记录为准。

正式业务从后续阶段按领域、用例、仓储与页面拆分；不能把临时计数器表扩展成工资数据库。

## 工具版本与完整性

Flutter 固定 3.47.7 的官方提交，Dart 实际版本 3.13.5。Android 编译/目标 SDK 36；构建声明最低 Android 24、iOS 15，这不是最低系统真机验收结果。依赖锁位于 pubspec.lock；工具及 Gradle 分发校验信息位于 toolchains.lock.json 和 Gradle wrapper。

SDK 从已核对的源码提交引导，下载源为该源码 engine.version 指定的官方对象。不能因为旧发布索引返回 404 就改成未知镜像，不能禁用 TLS 或改写预期校验和。

## 容器、信任与私有状态

宿主机用户目录不可写，ADB、Dart 分析器会尝试创建固定的用户状态目录。因此容器使用自然的 `/home/builder`，不修改 HOME。依赖、构建缓存和开发状态绑定到工作区；调试签名及 ADB 状态持久保存在工具目录，不提交 Git。

系统组合 CA 在运行时挂载到默认信任位置，Java 为当前会话生成临时信任库；会话 CA 不写进镜像层。沿用平台代理。容器以 UID 1000、4 个 CPU 和 8 GiB 上限运行，不使用特权或 host 网络。

## 原生文件接口

采用 file_picker 13.1.0 提供双端系统保存和打开接口。替代最初调查的 file_selector/分享组合，因为 file_selector 的保存位置 API 不支持安卓和 iOS。导出通过系统文件对话框写入用户选定位置，不要求其他应用接收分享。

平台验证文件最大 256 KiB，按流累计限制大小，再检查 UTF-8、JSON、整数版本和标识。正式工资备份将在阶段 5 单独定义格式和恢复事务。

## Android 构建适配

android_file_picker 2.1.1 内部声明 AGP 8.5.2 和 KGP 1.8.22。宿主工程使用 Flutter 模板固定的 AGP 9.1.0、KGP 2.4.0，通过宿主设置对该模块作版本对齐，不修改第三方缓存源码。升级 SDK 或该插件时须复查并在不再需要时移除对齐规则。

JetBrains 工件从 Maven Central 获取；Google Maven 仓库排除这类 group，包含插件后续加入的仓库。此调整解决云代理将不存在的 Google 路径转为上游 503、阻止 Gradle 回退的问题，不更改依赖自身版本或下载校验。实际遇到的 AndroidX 503 需在官方地址恢复 200 后重试，不循环执行未变化的失败命令。

## 模拟器与通知边界

云机没有 KVM，使用 API 36 AOSP x86_64、低分辨率、单核软件模拟；Google APIs 镜像首次启动过慢，未用它宣称任何应用测试通过。

已观察到系统主线程类加载超过 60 秒，Android Watchdog 杀死 system_server，应用尚未启动。按 Android 16 Watchdog 源码公开支持的 Settings.Global 设置，将该测试 AVD 的 watchdog_timeout_millis 调整到 300000。保留监控，不修改 APP 断言、系统完成标记或通知时间。该设置只适配软件模拟，不代表真机性能验证。

原生文件对话框由独立 ADB 驱动点击，Dart 用例仍要求真实 URI 和真实文件内容一致，不模拟方法通道或虚构成功。Android 构建及设备测试共享文件锁，避免覆盖同一输出。设备测试可能重写 app-debug.apk；提供给用户的 APK 必须从正常应用构建单独复制并计算 SHA-256，不能把测试入口 APK 当应用交付。

本地提醒的业务规则尚在阶段 6；当前仅验证单条测试通知的初始化、排程、查询与取消。送达、时区变化、长期后台、关机与双端真机仍须分别验收。

本机 JIT 测试 APK 安装失败，原生 Dart 集成用例尚未执行。另用显式打开平台验证的 x64 AOT profile 包进行系统 UI 检查，结果独立记录。该开发构建保持语义树可见，使 UIAutomator 能读取真实控件；AVD 通过 wm density 设置实际密度，避免设备模板密度导致视口过小。测试要求跨应用进程重启保留 SQLite 值、真实系统文件保存/读取、通知待处理状态及取消，不能把包安装成功当作这些检查通过。

## iOS 与 CI

iOS 工程和通知委托配置已生成，尚未通过 macOS/Xcode 构建及真机验证。GitHub Actions 通过开发分支运行，成功后上传 APK、校验值、构建来源和阶段说明；每次结果以对应运行记录为准。Linux 测试、Android 编译和 iPhone 行为必须分开报告。
