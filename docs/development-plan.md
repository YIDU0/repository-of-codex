# 个人工时与收入 APP：开发步骤方案

状态：用户已确认，阶段 0 完成，当前执行阶段 1。本文是执行计划，不是已完成报告。实际结果见 [phase-1.md](phase-1.md)。需求依据为 [requirements.md](requirements.md)，开发规则见 [development-rules.md](development-rules.md)。

## 1. 推荐技术方案

| 领域 | 建议 | 原因 |
| --- | --- | --- |
| 跨平台客户端 | Flutter + Dart 稳定版 | 共用两端页面和业务代码，适合定制手账风界面与离线应用 |
| 页面状态 | Riverpod | 页面状态与业务用例分离，方便替换数据来源和测试 |
| 页面路由 | go_router | 集中管理入口、编辑页及通知跳转 |
| 本地数据库 | SQLite + Drift | 类型化访问、事务、查询和版本迁移 |
| 提醒 | 经当前稳定版兼容性验证的本地通知插件及平台适配 | 对权限、时区、重启、取消与送达限制提供独立封装 |
| 文件与导出 | 系统文件选择和分享，版本化 JSON 备份、CSV 明细 | 便于用户持有数据，安卓苹果交换备份 |
| 测试 | Dart/Flutter 单元、组件、集成测试及两端真机验收 | 计算正确性与平台能力分别验证 |

具体 SDK 版本和依赖版本在阶段 1 根据官方稳定版、兼容矩阵和实际构建结果选定并锁定，不在未验证时杜撰版本号。应用包提交锁文件，新增依赖需有明确用途，优先使用仍维护且许可适用的组件。

## 2. 模块与依赖边界

建议目录：

```
lib/
  app/                     # 启动、路由、依赖组装
  core/
    money/                 # 精确金额与输入解析
    time/                  # 可注入时钟、当地日期及时区
    database/              # 数据库基础设施与迁移
    design_system/         # 主题与通用视觉组件
  features/
    time_entries/          # 日记录、休息、复制
    pay_rates/             # 时薪版本、快照、历史纠错
    adjustments/           # 每日加减项及常用模板
    statistics/            # 月年查询与展示
    reminders/             # 业务调度与平台通知适配
    backup/                # 备份、验证、恢复、CSV
    settings/              # 偏好设置与权限状态
test/
integration_test/
docs/
```

有实际业务逻辑的模块按 `domain / application / data / presentation` 划分；简单模块不机械创建空层。页面调用用例或控制器，数据访问通过接口，领域对象不依赖 Flutter、SQLite 或通知插件。首期直接支持三个明确定义的工资类别，不预先实现任意公式语言或插件系统。

## 3. 核心数据设计

| 数据 | 核心内容 |
| --- | --- |
| RateVersion | 标识、生效日期、三档时薪分值、创建/更新信息 |
| DayEntry | 唯一当地日期、工作或休息、备注、使用的版本信息、记录级收入分值、计算规则版本 |
| WorkLine | 日记录标识、工时类别、百分之一小时、时薪快照、单项收入分值 |
| AdjustmentLine | 日记录标识、名称快照、加减类型、金额分值、顺序 |
| AdjustmentTemplate | 名称、加减类型、默认金额、启用状态 |
| Preferences | 提醒开关和时间、界面偏好；不保存系统授权为可恢复事实 |
| CorrectionLog | 更正发生时间、原因、受影响记录及调整前后摘要 |

日记录收入可存为查询快照，但不能成为第二套独立计算逻辑：保存及纠错均调用同一计算器，写入同一事务，测试验证快照与明细一致性。月年汇总以已保存每日分值求和。

日期作为日历日期存储，修改时间作为带时区语义的时间戳存储，两者不得混用。备份携带独立的格式版本，不能仅依赖当前数据库内部表结构。

## 4. 分阶段执行与通过条件

每阶段按“实现 → 必要测试 → 整理实际结果 → 修复 → 进入下一阶段”推进。无需对每个可逆小改动反复请求同意；改变已确认需求、引入外部付费服务或执行破坏性数据操作时另行说明。

### 阶段 0：方案确认

产物：需求、开发步骤、开发规则三份文档；明确用户接受实施建议及提醒边界，记录待补设备信息。确认前不生成应用工程或实现业务代码。

通过条件：用户确认方案，或提出修改后完成修订；应用名称与设备截图不必阻挡领域开发。

### 阶段 1：工具链、最小工程与平台风险验证

1. 核对仓库和本地改动，复用现有 checkout，不自行新建 Git worktree。
2. 检查 SDK、JDK、Android SDK、硬件与磁盘；选择匹配稳定版并记录校验与版本。
3. 安装所需工具，初始化 Flutter 工程，建立目录、格式化、静态检查和测试入口。
4. 用最小骨架验证 SQLite 可读写、文件导出与选择、通知权限和待处理通知查询；尽早识别插件平台限制。
5. 在 Linux 构建 Android 最小调试包；在可用 Mac 上验证 iOS 编译及签名路径。没有 Mac 时明确标记 iOS 未验证，继续共享代码开发，不以 Android 通过替代。
6. 设置仓库开发约定、贡献说明和 CI 基线；保存可复现工具安装及启动步骤。

通过条件：已验证平台能启动最小应用、离线持久化成功；有实际可行的提醒调度方案和平台限制记录。iOS 条件不足单独保留为交付前置条件。

### 阶段 2：计算引擎、时薪版本与数据库

1. 实现工时、金额解析与格式化、整数计算器、日期分类和输入约束。
2. 定义日记录、明细与时薪版本，建立数据库约束、迁移与仓储接口。
3. 实现补记、修改保持快照、调薪生效边界、历史纠错影响预览和原子更新。
4. 先完成领域测试，再接数据库集成测试；覆盖舍入边界、负收入、周末、无适用费率及回滚。

通过条件：核心金额案例全部正确，调薪不静默改变历史，数据库关系及唯一日期约束有效。

### 阶段 3：视觉系统与每日记账闭环

1. 先完成主题样式和首页、月历、记录页的可操作界面原型。
2. 实现首次时薪配置、日期选择、两种字段布局、收入实时预览和保存。
3. 完成工作/休息/未记录转换、补记、修改、删除、备注和异常状态。
4. 加入常用加减项及跨日期类型复制，确认模板快照与历史互不影响。
5. 连接真实数据库，不把演示数据当已保存数据。

通过条件：首次设置到记录、关闭重开、修改及月历查看形成真实闭环；小屏、键盘和字体放大可用。

### 阶段 4：月年统计与 CSV

1. 构建统一统计查询，完成分类、月度、年度及逐日数据。
2. 完成图表、空数据、零收入和负收入展示。
3. 实现中文 CSV 导出、特殊字符转义与公式注入防护。
4. 验证月年边界、闰日及各页面金额对账。

通过条件：每日明细、月合计、年合计、CSV 数值一致。

### 阶段 5：备份、恢复与迁移

1. 实现版本化完整备份格式、导出告知与系统文件操作。
2. 实现导入校验、预览、替换确认、恢复前自动备份、事务回滚。
3. 模拟损坏文件、重复日期、未知版本、磁盘失败及中途失败；验证原数据不丢失。
4. 在两端测试同一备份文件，核对记录、时薪、模板、历史和统计。

通过条件：真实数据往返无损，异常恢复不破坏原数据，有旧格式迁移测试。

### 阶段 6：提醒完整集成

1. 将阶段 1 验证过的平台方案接入记录保存、删除、恢复、时间修改和应用生命周期。
2. 实现权限状态、提醒覆盖截止日期、待处理任务取消与补充、通知点击导航。
3. 验证当地日期及时区变化，记录长时间不开应用和系统后台限制的实际行为。
4. 两端真机验证已记录不再提醒、未记录能收到、关闭开关、拒绝权限、重启等场景。

通过条件：已声明的通知行为在目标真机有证据；覆盖范围和系统限制在界面及文档中一致。当前无法验证的场景明确列为未验收。

### 阶段 7：整体验收与测试包交付

1. 按需求 A01—A12 逐项验收，区分通过、失败和未运行。
2. 执行静态检查、单元/组件/集成测试、Android 构建和 Mac 上的 iOS 构建。
3. 检查无意数据上传、正式包日志、隐私提示、素材授权和版本标识。
4. 交付 Android APK 与安装说明；按账号条件交付 iOS 测试方案及构建。
5. 编写 README、架构及数据文档、备份说明、测试结果、已知限制和下一步建议。

通过条件：必需项全部有结果；存在未通过的平台或关键业务项时，不标记双端交付完成。

## 5. 必须持续执行的测试

- 计算：整数解析、0.005 舍入、分类先舍入、最大工时、负数净收入。
- 时薪：相邻生效日期、首次版本之前、未来版本、历史编辑、范围纠错及失败回滚。
- 数据：一日唯一、工作和休息互换、模板快照、复制映射、持久化和迁移。
- 统计：每日/月度/年度对账、跨年、闰日、空记录与负收入。
- 文件：中文及 CSV 特殊字符、恶意公式、备份版本、重复标识、无效引用、损坏和事务失败。
- 提醒：注入时钟的调度测试，加真实安卓和 iPhone 平台验证；明确调度正确与通知实际送达的区别。

## 6. 当前环境与安装交付条件

本次只读检查发现当前执行环境为 Linux，Java 可用，Flutter、Dart、Xcode 不在 PATH；这不是完整工具链验收，实际安装在方案获确认后进行。

Android 测试可使用 APK 安装，设备系统版本、架构及安装权限需后续核对。iOS 构建需要 macOS 与 Xcode，安装路径取决于设备和账号：

- 个人 Apple ID 配合 Mac/Xcode 可用于受限制的个人真机开发测试，签名有效期和配额按苹果当前规则验证，不能承诺永久安装。
- 通过 TestFlight 分发通常需要付费 Apple Developer Program，并满足上传、签名及相关审核要求。
- Linux 云端不能完成原生 iOS 构建或证明 iPhone 真机运行；后续可使用用户 Mac 或另行配置的 macOS 构建环境。

两端实际支持的最低系统版本，在阶段 1 结合目标手机与插件兼容性锁定。官方工具或依赖下载需要的域名在实际安装前核对；不因计划需要而预先拓宽网络权限。

不承诺当前尚未验证的安装成功、通知可靠性、iOS 构建结果或交付日期。每阶段完成时报告实际产物、验证证据和剩余条件。
